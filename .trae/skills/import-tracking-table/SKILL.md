# 工作任务跟踪表导入

## 描述

把用户每周维护的《工作任务跟踪表》（Markdown，含 emoji 状态标记）解析为结构化数据，导入部门管理系统。支持首次全量导入和后续每周增量同步。

## 使用场景

- 用户给出新的跟踪表 md 文件，要求「写入系统」「同步任务」「作为初始数据」时
- 用户问「跟踪表怎么导入」「任务状态怎么映射」时

## 指令

1. 读取 md 文件，提取「全部任务清单」表格的列：序号 / 任务板块 / 工作内容 / 时间节点 / 负责人 / 状态；同时读取「关键事项详情」「待补充/需说明事项」章节作为备注补充。
2. 状态与优先级映射（严格遵守）：

   | 表中标记 | 系统 status | 说明 |
   |---|---|---|
   | ⏳ 未开始 | `todo` | |
   | 🔄 进行中 | `in_progress` | |
   | ✅ 已结束 | `done` | completed_at 取表中结束日期；废标/终止类任务 priority 降为 `low` |
   | 🚧 阻塞 | `blocked` | 阻塞原因写入 description |
   | 🔴 紧急 | 不单独成状态 | 该行 status 按其描述（通常 in_progress），priority 设为 `urgent` |

3. 优先级补充规则：「本月必完成」章节中的任务 → `high`；「紧急/阻塞事项」表中 🟡 中紧急度 → `high`；其余 → `mid`。
4. 负责人处理：多负责人时取第一位为主负责人（写入 assignee_id），其余以「协助：某人（分工）」写入 description。
5. 标题格式：`任务板块｜工作内容`；description 第一行写 `【跟踪表序号 N】`，随后写协助人与备注。
6. 成员若不存在则先创建：用户名为姓名全拼、角色 staff、初始密码按项目惯例（管理员可后续重置）。
7. 执行导入脚本：在 `backend/` 目录运行 `python -m scripts.import_tracking`（脚本内维护最新任务数据；若任务内容有变化，先更新 `backend/scripts/import_tracking.py` 中的 `TASKS` 常量再运行）。
8. 脚本幂等：按标题查重，已存在的任务自动跳过；导入完成后输出新增/跳过统计。
9. 向用户汇报：新增几项、跳过几项、紧急/阻塞任务清单（提醒重点跟进项）。

## 示例

输入：「这是 v13 跟踪表，帮我同步进系统」（附 md 文件）
做法：解析 v13 与脚本内 v12 的差异 → 更新 `TASKS` 常量（新任务追加、状态变化修改）→ 运行导入脚本 → 汇报「新增 2 项、状态更新 3 项；当前紧急：锦水河西支支出（朱总催办）；阻塞：法院展厅、孔村项目」。
